#! Analyzing the Angular Project Structure
1. The root directory of the project contains configuration files such as `angular.json`, `tsconfig.json` and `package.json`.
2. src directory contains all the source code files. index.html is the main entry point of the application. styles.css is the main CSS file. main.ts is the main TypeScript file which is very important as it is the first code file to be executed when your angular application starts.
3. assets directory contains all the static assets such as images, fonts, etc.

#! Understanding Components and how contents ends up on the screen
1. index.html gets its custom components tags from main.ts file. The main.ts imports the required components from the app directory. The app directory contains all the components inside app.components.ts file.
** app.components.ts file:**
```
import { Component } from '@angular/core';
import { RouterOutlet } from '@angular/router';

#! @Component is a decorator used to add metadata about the component.
@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet],
  templateUrl: './app.component.html',
  styleUrl: './app.component.css'
})
export class AppComponent {
  title = 'first-angular-app';
}
```

#! Introducing Signals
** user.component.ts:**
"
import { Component, computed, signal } from '@angular/core';
import { DUMMY_USERS } from '../dummy-users';

const randomIndex = Math.floor(Math.random() * DUMMY_USERS.length);

@Component({
  selector: 'app-user',
  standalone: true,
  imports: [],
  templateUrl: './user.component.html',
  styleUrl: './user.component.css'
})

export class UserComponent {
  // selectedUser = DUMMY_USERS[randomIndex]; // Advantage of doing this is that we can now access this selectedUser inside the template of this component.
  selectedUser = signal(DUMMY_USERS[randomIndex]); //! using signals for state management
  imagePath = computed(() => `assets/users/${this.selectedUser().avatar}`); //! using computed for state management which uses signals under the hood

  //! This is a getter
  // get imagePath() {

    const randomIndex = Math.floor(Math.random() * DUMMY_USERS.length);

    this.selectedUser.set(DUMMY_USERS[randomIndex]); //! using signal's set method
  }
}

#! Working with Outputs and Emitting Data
When the user's click event is triggered, the onSelectUser method from user.component.ts is called. The emitted signal is then sent to the (select) event emitter. The (select) event then sends the emitted signal to the onSelectUser method of app.component.html which sends the emitted signal to the onSelectUser method from the app.component.ts which then console.logs the selected user's id.

** user.component.ts:**
```
import { Component, computed, EventEmitter, Input, input, Output, signal } from '@angular/core';

@Component({
  selector: 'app-user',
  standalone: true,
  imports: [],
  templateUrl: './user.component.html',
  styleUrl: './user.component.css',
})
export class UserComponent {
  //! Input decorator is used to receive data from the parent component to this child component
  @Input({required: true}) id!: string;
  @Input({required: true}) avatar!: string;
  @Input({required: true}) name!: string;

  //! Output decorator is used to send data from the child component to the parent component. In this case, it emits the id of the selected user. select is a custom named event
  @Output() select = new EventEmitter();

  //! This is a getter function
  get imagePath() {
    return `assets/users/${this.avatar}`;
  }

  onSelectUser() {
    this.select.emit(this.id);
  }
}
```
** user.component.html:**
```
<div>
    <button (click)="onSelectUser()">
        <!-- When using signals, we need to use parenthesis. For getter, we don't need parenthesis -->
        <img [src]="imagePath" [alt]="avatar">
        <span>{{ name }}</span>
    </button>
</div>
```

    if (tasks) {
      this.tasks = JSON.parse(tasks);
    }
  }

  getUserTasks(userId: string) {
    return this.tasks.filter((task) => task.userId === userId);

  }

  removeTask(id: string) {
    this.tasks = this.tasks.filter((task) => task.id !== id);

    this.saveTasks();
  }

  private saveTasks() {
    localStorage.setItem('tasks', JSON.stringify(this.tasks));

#! Module Summary
Here’s a short summary of the Angular module you provided, broken down into key points:

### Components
- **Components** are the building blocks for user interfaces in Angular.
- A **Component** is a class decorated with the `@Component` decorator, which contains the selector, template, styles, standalone and imports.
- **Component Tree**: Components can be nested within each other, forming a tree structure.
- **Inputs** allow a parent Component to pass data to a child Component.
- **Outputs** allow a child Component to send data or events back to the parent.

### Data Binding
- **String Interpolation**: Output property values in the template using `{{property}}`.
- **Property Binding**: Set a DOM property, like `src`, with `[property]="value"`.
- **Event Binding**: Listen to events (like clicks) using `(event)="method()"`.
- **Two-Way Binding**: Sync data between a form input and the model using `[(ngModel)]`.

### State Management
- **Zone.js** (default) watches for data changes and updates the UI.
- **Signals** (from Angular v16) require manual notifications of data changes, improving performance by targeting specific data updates. Also covered computed function.

### Conditional Rendering & Loops
- **@if Syntax** (from Angular v17) for conditional rendering, or use `ngIf` in earlier versions.
- **@for Syntax** (from Angular v17) for looping over arrays in templates, or use `ngFor` in earlier versions.

### CSS and Styles

#! Calculating the Annual Investment Data

** app.component.ts **
"
import { Component } from '@angular/core';
import { HeaderComponent } from './header/header.component';
import { UserInputComponent } from './user-input/user-input.component';

@Component({
  selector: 'app-root',
  standalone: true,

export class AppComponent {
  calculateInvestmentResults(data: {
    initialInvestment: number;
    duration: number;
    expectedReturn: number;
    annualInvestment: number;
  }) {
    const { initialInvestment, duration, expectedReturn, annualInvestment } =
      data;
    const annualData = [];
    let investmentValue = initialInvestment;

    for (let i = 0; i < duration; i++) {
      const year = i + 1;
      const interestEarnedInYear = investmentValue * (expectedReturn / 100);

        interest: interestEarnedInYear,
        valueEndOfYear: investmentValue,
        annualInvestment: annualInvestment,
        totalInterest: totalInterest,
        totalAmountInvested: initialInvestment + annualInvestment * year,
      });
    }

    return annualData;
  }
}

#! Cross-Component Communication with Outputs i.e @Output decorator and EventEmitter
1. We have our "Calculate" button in user-input component which is the child component of app component which is the parent and contains the calculateInvestmentResults function.
2. We can communicate with the parent component from the child component by emitting a signal from the child component and listening to the signal from the parent component using the output() function from angular/core.
3. We can communicate with the parrent component by emmiting a custom event from the child component and listening to the event from the parent component using the @Output() decorator and the EventEmitter() function from angular/core.

4. Emit the event from the child component's .ts file and listen to the event from the parent component's .html and .ts file

import { Component, EventEmitter, Output } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  selector: 'app-user-input',
  standalone: true,
  imports: [FormsModule],
  templateUrl: './user-input.component.html',
  styleUrl: './user-input.component.css',
})
export class UserInputComponent {
  @Output() calculate = new EventEmitter<{initialInvestment: number; duration: number; expectedReturn: number; annualInvestment: number;}>(); //! Approach 1: Generic and usable with any version of Angular

  enteredInitialInvestment = '0'; enteredAnnualInvestment = '0'; enteredExpectedReturn = '5'; enteredDuration = '10';

    //! Emitting an event is constant for any approach
    this.calculate.emit({
      //! + converts string to number
      initialInvestment: +this.enteredInitialInvestment, duration: +this.enteredDuration, expectedReturn: +this.enteredExpectedReturn, annualInvestment: +this.enteredAnnualInvestment
    })
  }
}

#! Understanding & Configuring View Encapsulation
In Angular, **View Encapsulation** is a mechanism that controls how styles defined in a component are applied and scoped. It helps prevent style conflicts between components by encapsulating styles within each component. There are three main types of view encapsulation strategies available in Angular:

## 1. **Emulated (Default)**
- **Description**: This is the default encapsulation mode in Angular. It emulates the behavior of the Shadow DOM by adding unique attributes to the component's HTML elements. These attributes ensure that styles defined within a component are scoped to that component only.
- **How It Works**: Angular adds a unique attribute (e.g., `_ngcontent`) to the component's elements and applies styles using these attributes. The styles are added to the `` section of the HTML document.
- **Advantages**: It does not require browser support for Shadow DOM, making it compatible with older browsers. It prevents styles from leaking out to other parts of the application.

## 2. **ShadowDom**
- **Description**: This encapsulation mode uses the browser's native Shadow DOM API to encapsulate styles. It creates a Shadow Root for the component, which isolates the component's styles from the rest of the document.
- **How It Works**: When a component uses Shadow DOM encapsulation, Angular creates a Shadow Root for the component. This Shadow Root acts as a boundary, ensuring that styles defined within the component do not affect other parts of the application.
- **Advantages**: It provides true isolation of styles, which can be beneficial for components that need to be reused across different applications or environments. However, it requires browser support for Shadow DOM, which might not be available in older browsers.

## 3. **None**
- **Description**: This encapsulation mode disables style encapsulation entirely. Styles defined in a component are applied globally, meaning they can affect any part of the application.
- **How It Works**: When encapsulation is set to `None`, Angular does not add any special attributes to the component's elements. Styles are applied directly to the document, allowing them to affect any element that matches the CSS selectors.
- **Advantages**: It is useful when you want to share styles across components or apply global styles. However, it can lead to unintended style conflicts if not managed carefully.

Each encapsulation strategy has its use cases depending on the requirements of your application. **Emulated** is suitable for most scenarios due to its compatibility and default behavior. **ShadowDom** offers true isolation but requires modern browser support. **None** is useful for global styling but requires careful management to avoid conflicts.
